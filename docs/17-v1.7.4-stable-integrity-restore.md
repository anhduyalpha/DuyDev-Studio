# v1.7.4 — Stable Integrity Restore

## Goal

Port only the verified-cookie Active Premium workflow and non-blocking loading animations back onto the stable v1.7.3 renderer. The DOM merge, fingerprint, retry, media wait, A4 layout and `Page.printToPDF` path remain the v1.7.3 implementation.

## Active Premium

1. Query all Chrome cookies and filter exact `studocu.com`, `*.studocu.com`, `studocu.vn`, and `*.studocu.vn` domains.
2. Show the gate in red and keep PDF/Queue actions locked while any cookie remains.
3. Delete cookies in parallel, including `storeId` and `partitionKey` where available.
4. Reload the current Studocu tab with cache bypass.
5. Wait for the tab to complete loading.
6. Delete cookies recreated during reload and require a short zero-cookie quiet window.
7. Store the green gate only after a final query returns zero cookies.
8. Any new Studocu cookie invalidates the gate through `chrome.cookies.onChanged`.

## Loading animation

- Popup: three bouncing dots and a progress shimmer while queued, recovering, scanning, or creating PDF.
- Page overlay: four-dot wave, pulsing detail text, and animated ellipsis from the first merge/analyze stage.
- Animations are CSS-only and stop when paused, completed, or failed.

## Integrity guarantee policy

The extension still uses the v1.7.3 stable path: clone full page DOM, preserve text/media/SVG/canvas, compare source and clone fingerprints, retry incomplete pages, wait for media/font completion, and abort rather than download when required data is missing. No v1.8.x fast print isolation or optimized renderer code was ported.
